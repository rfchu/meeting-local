# 跨会议引用问答验收

## 实现范围

单次检索后问答：关键词／语义／混合检索、模型选择、会议与资料类型筛选、明确的云端发送确认、引用预览、队列与取消、历史记录、来源变更失效、原文与音频跳转。不自动分析完整资料库，不采用旧问答作为上下文，不保证穷尽会议或引用的语义充分性。

上下文预算使用保守字符启发式，非模型 tokenizer 精确计数；单次输出上限 2048 tokens。默认仅文字稿，个人备注须主动开启；个人备注与会议简记的结论均强制标为线索。已采用简记的纪要在来源简记发生变化后不再作为当前检索依据，需重新核对整理。

## 自动验证

运行 `PYTHONPATH=. .venv/bin/pytest -q` 与 `npm --prefix frontend run test:stream`。新增 `tests/test_qa.py` 覆盖：

- 无依据不入队、正常生成、临时文件清理。
- 虚构编号、虚构摘录、无引用结论、简记冒充事实、错误的不足结构被拒绝；合法的依据不足响应。
- 个人备注在排名前排除，避免其挤占公开结果。
- 云端明确确认、目标配置绑定、密钥只通过子进程环境传递、禁止 HTTP 重定向。
- 排队与生成期间来源或配置变化、历史来源过期、来源会议删除清理关联记录。
- 取消不发布回答、子进程超时退出、中文检索词长度限制、JSON 重试保持输出预算。
- 已采用简记变化后，旧纪要检索与关联回答失效。

## 隔离页面验收

运行 `PYTHONPATH=. .venv/bin/python scripts/recording_ui_fixture.py --qa-demo`，打开 8766 端口。所有会议和音频为合成样例，使用临时数据库；不采集麦克风，不访问真实会议，不调用本地或云端模型。回答为固定生成器，仅验证真实队列、接口与界面，不能据此推断模型质量。

1. “搜索与引用问答 → 引用问答”，问题“交付时间发生了什么变化？”，关键词“交付”。
2. 预览显示两场会议的周五／下周一记载，生成后每条结论附连续摘录及核对入口。
3. 点击核对打开对应会议文字稿和音频；重新打开窗口后从历史恢复回答。
4. 选择云端模拟配置，预览后确认框未勾选时禁止生成，勾选后才可排队。此示例仍不访问外部模型。
5. 使用不匹配关键词，显示依据不足，无生成按钮。
6. 修改来源后历史回答隐藏，要求重新检索。

待真实资料评估：普通话项目名、人名、时间变更、跨会议冲突、资料无答案及个人观点混杂的召回率、引用支持程度与拒答质量。真实模型效果和长会议性能尚未完成本阶段评估。
