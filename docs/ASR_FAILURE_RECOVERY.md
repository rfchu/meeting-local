# 千问转写失败与恢复（2026-10-23）

本次确认两条独立路径：

- 精细转写：124 秒音频块的对齐结果达到 140.88 秒，严格范围校验拒绝结果；先前整场提交机制使已成功的分块无法在页面直接查看。
- 快速完成：补识别窗口最多 15 秒，但原来的解码上限重试仅允许超过 20 秒的输入再分割，短片段达到上限时没有重试路径。

## 修复

1. 保持强制对齐原有严格校验。对齐不可用时仅保留 ASR 已完成文字和整个块的真实起止范围，不按字符虚构时间；片段记录 `timestamp_precision=chunk`、`alignment_warning`，页面显示“时间待校准”。粗时间块不自动归给某个发言人，也不与连续短句合并；人工保存保留警告。
2. 非流式解码达到输出上限后，丢弃截断结果并递归拆小音频，直到不再截断；最短 2 秒或最多 7 层后仍异常则明确失败。全零 PCM 不调用识别模型。实时 token 流仍保留原有“必须完整结束才算覆盖”的校验，不把未完成预览当作成功。
3. 失败时从当前任务检查点、快速完成时固定的实时结果快照，以及已完成 ASR 的对齐失败原始文件生成恢复候选稿。标出缺段，支持查看、复制和 JSON 导出；不自动覆盖当前文稿，也不把不完整稿交给会议分析或纪要。恢复稿导出包含 incomplete 和缺段元数据。
4. 同一任务重试复用成功检查点。已保存的完整解码及对齐信息可直接恢复为精确／粗时间片段，不再重新识别同一个对齐失败块。当前任务完整成功后清除该任务的未完成候选稿；其他历史恢复稿保留。
5. 千问检查点允许上述脚本修复升级，模型、运行环境文件身份仍须一致；模型文件改变继续拒绝复用，其他引擎保持原规则。
