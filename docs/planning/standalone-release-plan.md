# 听记独立发行技术方案

范围以已确认的[能力地图](../specs/MAP-standalone-distribution.md)及四份模块规格为准。目标是在没有开发环境的 Apple Silicon Mac 上，从公证 DMG 安装听记，再安装模型包、完成双轨录音和本地转写。LLM 由用户自行配置。最低系统按 macOS 15 验证，首版采用手动更新。本文为实施评审稿，任务状态见[独立发行任务清单](standalone-release-tasks.md)。

## 模块依赖与优先级

| 模块 | 优先级 | 任务与前置条件 |
| --- | --- | --- |
| 独立运行 | P0 | D01–D05。先验证包内运行时、原生采集和 MLX，再接入正式启动链路与写入保护。D03 的首页体验见[低保真评审](standalone-home-review.md) |
| 模型包 | P0 | D06–D10。清单可在运行时开发期间准备，安装切换依赖工作区及生命周期契约 |
| LLM 引导 | P0 | D11–D12。运行底座可用后，可与模型包并行开发。集成验收需要本地转写可用 |
| 发行与迁移 | P0 | D13–D17。签名样包可提前做，公开发行依赖全部能力与干净机证据 |
| 发行后候选 | P1 | 下载断点续传、多个模型包、在位引用外部目录。按内测数据评审后另拆任务 |
| 独立决策 | P2 | 自动更新、App Store、Intel 或更早 macOS 支持。各自需要单独验证 |

P0 是公开发布的必过项。没有签名资源时仍可在内部推进运行时与合成测试，公证和公开发布保持待验。

## 技术方案

### 独立运行

- 保留 Swift 宿主、WebKit、FastAPI 和独立采集协议。发行模式由宿主相对 App 包定位 Python、后端、前端静态资源及采集工具，沿用本地原生 ASR。源码模式继续使用现有路径入口。先用隔离样包验证 FFmpeg、Python 原生扩展和 MLX 可在无开发环境下运行，再确定运行时封装形式。
- 包内资源按只读处理。应用数据、模型和备份位于用户管理的包外目录，分别管理。工作区保留稳定的身份和版本标识。发布清单记录内置组件及版本，运行管理显示实际使用的包、数据和模型位置。
- 复用已有宿主身份和录音租约，补上发行模式的服务身份与本机写入授权。宿主管理启动、重连和受控退出，采集进程继续拥有写入生命周期。端口冲突只能选择安全的新端口或提示错误。内嵌界面、轻岛和现有浏览器入口都需验证其连接边界。
- 首先证明录音、保存、重开和回听可在缺少模型时完成，再验证模型就绪后可进入转写。工作台与轻岛继续读取同一场录音及翻译配置。

### 模型包

- App 内置可信发行清单或信任锚。清单将能力映射到版本、相对路径、大小及 SHA-256。兼容版本和完整包能力清单随发行记录发布。由项目提供的下载地址和用户指定的镜像都使用同一校验规则。
- URL 下载、本地压缩包和已有目录统一进入暂存、校验、待切换、启用流程。复制时沿用现有 `models/` 布局。先验证相对路径和容量，再核对全部文件。记录阶段与失败原因，网络失败可重试，取消清理暂存内容。
- 启用前检查活跃录音、试录和模型任务，使用与读者协调的切换机制。正在使用的任务继续持有原模型版本，成功后再更新活跃模型根。退出或崩溃后可辨别在用版本和未完成安装。

### LLM 配置与发行

- 复用运行管理的配置与连接测试。引导从功能入口回到对应场景，允许跳过。测试使用健康检查或合成文本，云端会议数据继续受独立确认约束。
- 发布构建使用固定版本和依赖锁定。先用同一签名身份验证宿主、采集器和 Python 原生依赖的签名、公证与启动，再打包最终 DMG。正式环境的权重、会议资料和开发路径不进入产物。
- 旧资料通过备份导入到独立工作区，源目录只读。导入和升级各自检查版本与容量，提供恢复入口。更新前核对录音租约和写入状态。回退时检查数据兼容性，必要时从更新前备份恢复。

## 决策与阻断项

| 项目 | 最晚决策点 | 如何关闭 |
| --- | --- | --- |
| Python／MLX 运行时封装及原生依赖重定位 | D01 本机样包已验证，D13–D15 关闭正式发行边界 | 已验证搬移及库来源。后续锁定发行运行时与 FFmpeg 来源，核对许可并补最低系统及干净机实测 |
| 发行 Bundle ID、Developer ID 与权限归属 | D02 开始前确定候选身份，D13 签名样包定案 | 核对宿主和采集组件身份，验证首次授权及覆盖安装 |
| 完整模型包组件、再分发条款与下载地址 | D06 确定组件，D15 前确定产物与下载来源 | 核对模型来源、条款、版本和体积，发布同版本可信清单 |
| 最低设备与公开下载渠道 | D17 前 | 至少覆盖最低支持系统及一台目标设备，记录芯片、内存及设备矩阵；缺失证据的能力留待验证 |
| 旧库与正式签名测试资源 | D13、D14 前 | 准备隔离的脱敏备份、签名权限和实机；实际会议资料留在本机 |

## 验证约定

任务先用临时工作区、合成音频或模拟接口验证正常和失败路径，再在每个检查点做跨组件演练。涉及真实设备、签名和模型的验收单独留证，自动化通过不能代替实测。前端改动运行 `cd frontend && npm run typecheck && npm run test:stream && npm run build`，原生改动运行 `bash scripts/test_host.sh`。后端回归从仓库根运行 `PYTHONPATH=. .venv/bin/pytest -q`，历史失败需记录基线并确认无新增差异。
