## 拟采用的设计

1. 使用现有会后交接和任务状态作为整理工作区入口。保存成功后用会议 ID 定位，保存失败时沿用录音恢复记录。
2. 译文关联稳定原文片段及输入版本。优先验证短样本在当前模型和任务队列中的中英混说表现，再扩展批量和会中处理。需要持久化结构变更时，在动工前按现有迁移规程明确兼容与回退。
3. 纪要任务绑定输入覆盖范围和有效记录版本，沿用独立草稿、人工采用及来源核对。派生译文供阅读与整理，引用校验依赖原文。
4. 受众投影在确认时形成独立快照。预览、确认及各格式导出共用同一份内容。受众筛选在服务端校验，包括附件字段和引用。
5. 跟进消费已核对的行动项。索引只收录有效且允许检索的内容。同源原文与译文使用同一来源身份，历史问答保存自身证据快照。

| 风险 | 验证方法 |
| --- | --- |
| 中英混说时引擎无法可靠标注片段语言 | T04 先跑固定合成样本及本机模型冒烟。未知语言走显式待确认路径，记录能通过验收的组合 |
| 迟到译文、并发确认或内容改动产生错误结果 | T05、T09、T11 用有控制的乱序与并发输入核对版本校验 |
| 对外版从标题、引用或导出模板带出内部字段 | T10、T12 用带可识别标记的样本核对预览和三种实际文件 |
| 真实设备或外部软件切换影响录音 | T16 使用有可核对声音的实机录音。实际未复现与待验证分别登记 |

评审时确认译文使用的本机模型、译文存储迁移方式和会中积压时的资源预算。这些选择由样本验证决定，当前任务清单使用现有配置接口和可替换模型作为前提。
