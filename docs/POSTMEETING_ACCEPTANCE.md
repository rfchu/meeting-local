# 会后整理与核对进度验收

核对清单分为文字稿与主题、发言人、简记与用途、纪要发送前检查。明确人工点击才保存确认，AI 生成结果不自动通过；发言人可选择本次不区分，无简记时显示无需核对。清单不阻止单独使用生成、预览或导出，不自动发送资料。

进度保存在 SQLite 的 `meeting_reviews` 表，绑定内容指纹。保存的是每项最近一次确认，不是完整审核审计日志。内容变化后不复用旧确认：文字稿版本影响所有相关项，主题影响文字稿和纪要，简记修改影响简记核对，采用到纪要的简记变化也影响发送前检查，重新生成或保存纪要影响发送前检查。未保存文字或纪要不能标记相应检查完成。旧页面以过期指纹确认时返回冲突，不覆盖新内容。

自动测试：`PYTHONPATH=. .venv/bin/pytest -q`、`npm --prefix frontend run test:stream`、`npm --prefix frontend run build`。覆盖刷新／重启恢复、撤回、跳过限制、版本变更、简记变化、纪要替换、主题修改、已采用来源变化、删除清理和过期提交。

可重复页面验收：运行 `PYTHONPATH=. .venv/bin/python scripts/recording_ui_fixture.py --review-demo`，打开 `http://127.0.0.1:8766/` 的“合成验收会议”。它预置合成文字稿、个人简记和 AI 样式纪要，不运行真实 AI 或采集设备，不使用用户数据库。

已验证：四项确认（含发言人不区分）完成后直接进入预览引导，无需会议分析；刷新并重新打开后保留 4/4；修改文字稿后立即撤销旧完成显示，保存为新版本后对应项待复核且旧纪要等待更新。另以桌面和窄窗口检查清单布局。合成示例只证明流程可用，不证明真实纪要内容的准确性。
