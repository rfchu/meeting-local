# 独立 App 运行规格

## 目标与范围

用户从 DMG 安装后，双击听记即可打开工作台。App 随包交付 Swift 宿主、内嵌前端、FastAPI 后台、独立采集组件、固定版本的 Python 运行时及音频工具。运行时路径从 App 定位，业务数据和备份写入用户数据目录，模型通过独立模型根目录读取。

沿用 Swift、WebKit、React、FastAPI 和 SQLite。复用现有宿主、采集控制、运行管理与诊断。涉及源码的位置为 `native/Host/`、`app/` 和 `scripts/`，测试沿用 Swift 宿主测试及 Python 集成测试。

## 用户流程与异常

- 首次打开时建立用户数据目录，验证后台身份及版本兼容性后进入工作台。随包组件缺失、启动失败或数据不可写时，在原生窗口提供失败原因和重试入口。
- 工作台和轻岛读取同一服务状态。服务使用本机回环连接，写入及录音控制入口验证授权。若端口被占用，使用安全分配的本机端口，或显示可操作的错误。不得连接或停止身份不符的服务。
- 应用再次打开时复用自己的服务。用户退出时，明确提示活跃录音和未保存状态，沿用独立采集及恢复协议。后台异常时提供重连或恢复入口，保留已落盘内容。
- 缺少听记模型时允许录音、回听和导入音频。需要模型的操作进入模型安装引导。缺少 LLM 的处理见 [LLM 配置规格](SPEC-llm-setup.md)。

## 验收标准

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| RT-01 | 在没有源码、Homebrew、开发工具和系统 Python 依赖的目标 Mac 上打开 App | 工作台可用，后台与采集组件从包内启动，诊断可以确认运行版本 |
| RT-02 | 拒绝麦克风或系统音频权限，再授权重试 | 拒绝时指出对应权限，重试后能采集；启动失败的空会话不会冒充已录音 |
| RT-03 | 录制双音轨并在录音期间模拟后台退出 | 已落盘音轨可恢复；界面区分录音、保存和识别状态 |
| RT-04 | 启动同名外部服务或再次打开听记 | 不误连外部服务，也不重复启动本场采集 |
| RT-05 | 在没有 ASR 模型和 LLM 时录音、保存、重开和回听 | 基础功能可用，所需模型的引导与真实状态一致 |
| RT-06 | 分别从空工作区、已有资料库、活跃录音或待恢复状态打开 App | 后台就绪直达工作台或可核实的原会话。恢复提醒只针对有可处理内容的记录，归属不明时提示核对。 |

已有验证入口为 `bash scripts/test_host.sh`、`bash scripts/test_host_web.sh` 和 `PYTHONPATH=. .venv/bin/pytest -q tests/test_workspace_binding.py tests/test_host_delivery.py`。独立包的安装和真实采集另做实机验证。

首版沿用原生录音架构。运行时打包方式、进程身份验证协议及具体数据目录名在技术方案阶段确认。
