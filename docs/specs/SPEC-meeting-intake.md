# 会议入口与会后交接

模块 `meeting-intake`。P0。覆盖 PRD P0-01、02、11、12。依赖现有采集与会后交接。见[共用规格](SPEC-workflow-common.md)。

用户可从线上、现场／混合或导入开始。保留实际音源选择和试录，场景入口负责说明本次采集范围，会议类型和议程可事后补填。会中继续使用简记、实时文字与概览。结束后按本场处理方案保存或提交任务，并进入对应会议的整理工作区。界面分别显示已保存音频、识别待处理范围及实际缺失范围。导入提交后同样可以进入对应会议查看进度。

| ID | 操作与异常 | 验收 |
| --- | --- | --- |
| MI-01 | 分别使用三类入口，试录或导入后刷新 | 场景、实际音源和会议对应一致，返回同一场会议。导入显示文件来源 |
| MI-02 | 保存成功、重复结束、保存失败后重试 | 同次录音只交接到一场会议。保存失败留在恢复路径，可找回已保存材料。沿用本场会后处理选择 |
| MI-03 | 识别中断、采集缺段或模型不可用 | 音频可回听，待识别与实际缺失分别展示。补识别只处理可用范围，重复执行不重复发布有效片段 |
| MI-04 | 真实线上及混合场景录制可辨识测试声音 | 核对实际音源、结束保存及回听。故障注入另验状态表达，真实设备结论记录设备和环境 |

复用 `app/meeting_handoff.py`、`app/recording_completion.py`、`frontend/src/features/notes/`。基线命令 `.venv/bin/python -m pytest tests/test_meeting_handoff.py tests/test_recording_completion.py tests/test_recording_faults.py -q`。
