# 会中工作台与伴随轻岛规格

状态：待评审。适用入口为浏览器工作台、macOS 内嵌工作台和原生伴随轻岛。沿用《[全流程模块共用规格](SPEC-workflow-common.md)》的技术栈、代码规范和数据边界。已确认的使用方式是会中默认看实时文字，需要时筛看标记和简记。以下状态契约、调度顺序和跨窗口交互是待评审设计。

## 现状与证据

| 发现 | 代码依据与结论 |
|---|---|
| 看板覆盖正文 | [全局样式](../../frontend/src/style.css#L82)将所有 `aside` 固定在左侧，[看板](../../frontend/src/features/copilot/ExtractedSidebar.tsx#L17)继承该定位。开启伴随时间线时，[原工作区](../../frontend/src/features/notes/RecordingView.tsx#L574)仍同时渲染。 |
| 浏览器工作台没有跟到正在录的会议 | [宿主浏览器入口](../../native/Host/AppDelegate.swift#L296)打开根 URL，没有传录音 ID。原生录音归后台，浏览器麦克风归启动录音的标签页；两者有不同的控制边界。当前[前端启动保护](../../frontend/src/features/notes/useRecordingController.ts#L1226)会拦截已持有原生采集锁时的重复启动。这可解释「切过去看不到原会话，重新开始又失败」，但尚未验证该次浏览器失败是否属于此路径。新开浏览器录音失败须单独检查音源选择、站点或系统权限及会话错误。 |
| 轻岛可能绑定旧会话 | [轻岛轮询](../../native/Host/CompanionController.swift#L206)首次发现录音后把 ID 留在当前窗口实例，后续按 ID 查询。若旧会话结束且轻岛持续打开，新会话不会被自动发现。重新打开轻岛会清空绑定。截图无法证明实测命中了这条路径，也无法证明宿主连接或响应校验正常。 |
| 轻岛内容与录音状态有不同前提 | [伴随投影](../../app/companion.py)的状态来自录音运行态，双语读取已确认原文及缓存译文，重点读取概览。截图中的概览为「未开启」，没有概览重点符合当前逻辑，但不能解释录音状态和已确认原文也不更新。原生波形目前只读取原生采集诊断。 |

## 会中界面

- 页签只有「实时文字」「AI 概览」，默认实时文字。统一页头负责标记、暂停、结束，页底状态栏呈现采集、保存和识别状态。详细波形及诊断按需展开。
- 实时文字按时间展示确认片段、临时文字、标记和我的简记。提供「全部／仅标记／仅简记／已采纳」筛选，以及原文与双语切换。切筛选保留输入草稿；从概览跳回原话时临时显示目标及上下文，标明时间和音轨，提供返回概览。会中定位原文，会后可按音轨回听。手动回看时新文字只增加提示；返回最新后继续跟随。
- 速记使用一个入口，保存原文立即返回，扩写单独触发并异步更新。宽窗可展开简记，窄窗用抽屉；页签、正文时间戳、输入和结束按钮始终可用。AI 概览默认不铺满空白看板，按议题呈现要点，汇总结论、待办和术语。概览未开启时仍可跟读和记笔记。
- 伴随时间线作为实时文字的呈现方式保留，会后历史入口和既有数据纳入回归。原生轻岛继续作为独立窗口存在，默认状态模式，用户可切双语或重点。

## 候选到采纳

- 规则提示和概览产出均可提出候选。候选须带录音 ID、类型、原文锚点、音轨与来源修订号。对同一证据的重复提示共用处置状态；不同证据或双轨同时发言分别保留，不能仅凭近似文字合并。
- 候选初始为「待核对」，可采纳或忽略。采纳生成可回溯的已确认事项；重试和跨窗口重复点击最多产生一条。忽略同一候选后持续生效；提示淡出只隐藏提醒。支持撤销采纳，保留来源关联。
- 来源修订后标记「原文已更新，待复核」，保留已人工确认的文字及原证据，禁止 AI 静默覆盖。原文定位失败时明确说明，并保留时间范围。用户直接保存的简记独立于候选流，未确认候选不作为正式决议、待办或对外交付内容。

## 推理资源

- 采集和写盘独立于模型。实时 ASR 在共享资源上优先；按实际申请的槽位仲裁，不能把排队优先级理解为中断运行中的请求或隔离 GPU。临时文字沿用已有识别流。
- 建议本地槽位按「实时双语翻译 → 会中概览 → 手动扩写 → 会后批任务」仲裁。概览同一会话最多一项在跑、一项合并等待；翻译以来源版本去重并复用缓存。持续翻译时为已等待的概览提供轮转机会，具体阈值由基线测量确定。候选规则与读取轻岛内容不发模型请求。云端概览用现有云端槽位及授权；本地资源忙时不自动转云端。
- 界面区分未开启、等待新文字、等待资源、生成中、失败与待重试。保留上一版成功内容和原文。扩写失败保留速记，录音继续；客户端超时不提前释放仍在执行的请求占用的槽位。

## 会话切换与轻岛

- 后台运行态为事实来源，统一按工作区及录音 ID 核对。存在唯一在录会话时，从宿主打开浏览器应携带或发现同一 ID，直接展示本场状态。没有会话时进入正常开录流程，多场时让用户选择，工作区不匹配时提示核对连接。
- 原生采集跨工作台继续运行。新工作台默认只读，控制有效时引导回原控制端；只有后台允许恢复时才提供显式操作。切换时不得自动启动、停止或抢占采集。浏览器录音的控制留在原标签页，其他入口显示已同步状态及原标签页指引；关闭原页后明确展示中断或待恢复状态。
- 轻岛自动跟随唯一活跃录音，旧会话结束后解除自动绑定；主动定位某场时明确显示当前会话。轻岛状态、字幕、重点按同一 ID 与版本展示。状态独立更新；双语分辨等待原文和等待译文；重点区分未开启概览、等待首版、已有内容和连接异常。优先复用概览与已采纳条目，标明状态，避免重复显示。轻岛不得因切模式启动识别、翻译或概览。连接过期时停止展示旧文字，返回本场只跳转已核对的会话。

## 验收

| 场景 | 通过条件 |
|---|---|
| 布局与定位 | 在内嵌和浏览器以 768、1024、1440 CSS px 验证；无侧栏遮挡或页面横向溢出。切筛选保留草稿；跟随、回看、双轨原话定位正确。 |
| 事项一致性 | 同一候选从提示或概览采纳，另一入口同步，重复操作仅保存一条。忽略、撤销、来源修订及同句双轨分别验证。 |
| 并发与降级 | 固定音频在同机、同配置下对比仅 ASR 和并行启用双语、概览、扩写两组。记录首字 P50/P95、确认文字滞后、概览等待和音轨落盘；建议门槛为并发首字 P95 较基线增量不超过 1 秒，音轨无新增缺段，槽位调用与排队能逐项核查。模型超时或拒绝时原文与简记可用，空闲后概览仍可更新。 |
| 跨工作台 | 通过宿主先发起原生录音再打开浏览器，验证相同录音 ID、音轨持续增长、无重复采集且控制边界清晰；另从浏览器新开麦克风录音，验证权限拒绝提示和其他页面只读。 |
| 轻岛跨会话 | 轻岛持续打开完成 A 场后启动 B 场，显示 B 的状态、原文、缓存译文及概览重点。关闭概览仍显示状态和原文。断连、旧响应迟到、多会话和错误工作区不能串场。核对轻岛只读轮询无额外推理调用。 |

## 首批验证记录

- Chrome 正式工作台先显示旧会话的恢复界面。暂存旧会话后，默认选中的原生双轨不可用。切到浏览器麦克风后，两次实机短测均进入录音，音量有变化，分段同步并完成保存。本次未观察到内嵌工作台占用导致浏览器麦克风失败。
- 第二次实机短录音期间，正式服务的轻岛投影返回 `multiple`，没有当前会话 ID。录音前同一接口返回旧浏览器会话的 `unknown`。隔离回归验证修订后优先选择唯一活跃会话，同时保留真实多场提示和按 ID 查看旧会话。
- 新版宿主完成隔离构建和签名，前端完成类型检查、流式测试与隔离构建。新版尚需在正式宿主和浏览器验证跨窗口跳转、轻岛连续跟随、双语与重点，以及不同宽度下的布局。候选跨入口共用处置状态和推理调度仍按规格单独验收。
