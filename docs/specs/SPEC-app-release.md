# macOS 发行与迁移规格

## 目标与范围

首版交付面向 Apple Silicon 的签名与公证 DMG，采用拖入「应用程序」安装。App、模型、会议资料独立存放。首版采用手动更新，支持从当前源码部署导出的备份导入，优先交付小范围内测。

复用现有宿主交付、备份恢复、录音租约和发行就绪检查。正式发行包使用独立发行配置，签名、公证结果、构建版本、校验值和组件清单均可核对。发行签名身份与采集组件身份在升级链路中保持稳定。

## 升级与异常

- 安装时建立独立用户工作区。导入旧资料前显示来源、版本、预计容量和导入范围，默认从备份导入。导入失败保持源资料和当前工作区可用。
- 更新前检查进行中的录音、试录和数据写入。存在活动任务时提示延后。升级涉及数据迁移时，先建立可恢复备份，并给出失败后的恢复入口。
- 模型包更新独立于 App。应用升级后复用兼容版本。需要回退时按数据库兼容性决定可否直接切换，或通过升级前备份恢复。
- 发行包仅包含可交付组件。签名密钥、凭据、真实录音、开发机路径和私人模型配置不得进入发行产物。

## 验收标准

| ID | 操作 | 通过条件 |
| --- | --- | --- |
| RL-01 | 在干净 Mac 下载、安装并首次打开发行 DMG | 系统正常校验签名和公证，宿主可启动，麦克风与系统音频权限流程清晰 |
| RL-02 | 在同一台 Mac 安装模型并完成双轨会议 | 能录音、转写、保存、重开和导出文字稿，分别回听两条音轨 |
| RL-03 | 从源码版备份导入一套含录音、文字稿、简记、纪要的资料库 | 对比导入前后数量并抽样核对原文、音频和版本，源数据完整 |
| RL-04 | 活跃录音时尝试更新，再结束录音并更新 | 活跃时延后，更新后历史会议和兼容模型仍可用，并验证权限可用或可按指引恢复 |
| RL-05 | 模拟安装失败或数据迁移失败，再演练回退 | 保留可启动版本或明确的恢复路径，会议资料可从备份核对 |
| RL-06 | 核对可下载产物 | App 版本、DMG 校验值、公证凭据和组件清单与发布记录一致 |

复用 `PYTHONPATH=. .venv/bin/pytest -q tests/test_host_delivery.py tests/test_workspace_iteration.py` 作为已有回归入口。干净机验收另记录系统与芯片、安装来源、签名验证、录音回听和迁移结果。

发行身份、下载渠道与首批支持设备名单待确认。自动更新和 Mac App Store 发行另行评审。
