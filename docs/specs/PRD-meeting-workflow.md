## 目标与默认提案

面向需要主持、记录、整理或跟进会议的人。一次会议形成可回听的记录、可核对的纪要、按受众确认的交付版本和可持续跟进的行动项。三种入口共用这一流程：线上录音、现场或混合录音、导入已有录音。

已明确的需求是支持项目推进、客户沟通、内部讨论和面试，纪要用于内部同步和对外分享。外语会议需要会中可看译文，会后可用中文整理和跨会议检索，保留原文及录音供核对。

以下是首版拟采用的默认值，供审核：

- 以现有 Mac 本机工作台为入口，优先复用已有录音、模型、存储和任务能力。
- 中文作为默认整理和检索语言，原文和译文可切换。首版对中文、英文及中英混说场景验收，其他语言按实际通过的场景逐步开放。
- 录音结束后自动进入同一场会议的整理界面，展示处理进度。沿用用户已选的会后处理方式，支持仅保存和手动生成。
- 对外分享通过预览、确认并导出完成。导出记录表示已生成交付件，发送状态由用户另行确认。
- 内部和对外交付使用同一场会议的已核对内容，分别确认和保存。对外内容由明确选中的条目组成。

## 会议类型与受众

会议类型决定草稿内容，受众决定交付时包含哪些条目。同一场客户会议可以同时保留内部推进纪要与客户确认稿。

| 类型 | 草稿重点 | 对外版可选内容 |
| --- | --- | --- |
| 项目推进 | 进度、决策、阻塞、依赖、负责人和日期 | 已确认的里程碑、变更及双方行动 |
| 客户沟通 | 客户诉求、共识、承诺、待确认问题 | 双方共识、已确认承诺和下一步 |
| 内部讨论 | 议题、分歧、决策理由、未决问题 | 经确认可分享的结论或约定 |
| 面试 | 问答、候选人陈述、事实与待核实项 | 明确选入的面试信息或后续安排，内部评语保留在内部版 |

AI 整理事实与待核实项。面试评语和最终决定由面试官填写。负责人、日期、承诺和决策缺少依据时，草稿显示待确认。

## 用户流程

| 阶段 | 用户操作 | 页面结果 |
| --- | --- | --- |
| 开始 | 选择线上、现场／混合或导入，按需选会议类型、项目或系列 | 显示实际音源与上次方案，可试录。项目、类型和议程可会后补齐 |
| 会中 | 查看文字或译文，标记决定、问题、待办或个人备注 | 采集、落盘和识别各自可辨。暂停跟随时可回看。个人备注与可用于纪要的关注点分开 |
| 会后交接 | 停止或完成导入，打开整理工作区 | 显示已保存材料、处理中的范围、缺段和下一步。任务失败时可继续使用已经保存的内容 |
| 整理与核对 | 生成草稿，核对关键条目或编辑 | 中文原文及有效中文译文按时间组成一份记录。点击关键条目可看原文、译文并回听。处理中的译文范围可见 |
| 交付 | 选择内部版或对外版，预览、确认、导出 | 每版保留对应内容和确认时的版本。刷新或重新生成草稿后仍能找到旧交付件 |
| 跟进 | 确认待办，更新状态，检索历史 | 按项目或系列查看负责人、日期、状态及来源。下一场会议能查看未完成事项。可用中文找到外语会议中的相关片段 |

## 能力地图与首版范围

P0 为首版闭环的发布门槛，P1 为下一轮主动优化。依赖表示消费前一项的成果。录音保存、手工整理与查阅原文在翻译或模型不可用时仍可继续。

| 模块 ID | 直接复用 | 需要优化 | 需要新增 | 依赖 |
| --- | --- | --- | --- | --- |
| `meeting-intake` | 原生系统音频和双轨、浏览器麦克风、导入、试录、会前准备、录音恢复、会中简记与概览 | 按场景组织入口，突出实际音源、保存状态和异常处置。统一导入与录音结束后的整理入口 | P0 同一场会议的入口选择及交接体验 | — |
| `chinese-record` | 原文语言、实时确认片段、补转写、时间戳、来源版本及模型配置 | 会中原文／双语切换，展示缺译、失败和过期区间 | P0 已确认外语片段的中文译文及其与原文的对应关系。会后中文记录供纪要与检索消费 | `meeting-intake` |
| `minutes-review` | 通用、项目例会、客户访谈和面试模板。草稿、采用、差异比较和逐条回听 | 用四类场景呈现模板。把来源核对和草稿编辑集中在会后工作区，内部讨论沿用通用模板 | P0 使用有效中文记录生成草稿，并让每项关键结论回到相应原文 | `meeting-intake`、`chinese-record` |
| `audience-delivery` | 现有受众选项、交付核对、快照、Word／PDF／Markdown 导出 | 从同一采用稿选择受众、核对条目及预览 | P0 同一会议分别确认和保存内部版、对外版。对外版按明确选入内容生成，导出与实际预览一致 | `minutes-review` |
| `meeting-followup` | 行动项、系列、来源定位、跨会议搜索与引用问答 | 会后确认待办并接续到下一场。按项目或系列查看记录和行动 | P0 中文查询可命中外语译文，结果标明译文并定位原文。受限内容沿用原有可见范围 | `minutes-review`、`chinese-record` |

建议依赖顺序为 `meeting-intake` → `chinese-record` → `minutes-review` → `audience-delivery` 和 `meeting-followup`。这是规格审核与集成的先后关系。跟进可以使用已核对纪要，无需等待纪要交付。

| 优先级 | 范围 |
| --- | --- |
| P0 首版 | 三种来源走通同一整理流程，四类纪要按受众交付，中文和英文会议可核对并跟进，中文可检索英文会议内容。保存、翻译、生成失败均有可见状态和可继续操作的路径 |
| P1 体验主线 | 扩大会议工作台的有效操作区，重做会中概览、纪要与文字记录的阅读及回听体验，优化只读伴随窗 |
| P1 语言扩展 | 按场显式选择主语言。首个验证候选为日语，按已验证的引擎与处理阶段开放 |
| 按问题处理 | 录音可靠性随实际问题定向跟进。Lark 共享接收端验收暂缓 |

活跃事项、顺序与验收见[实施计划](../planning/plan.md#当前任务分级)。语音同传、自动设备切换实现、自动发送、第三方任务同步和独立安装发行移出当前开发范围。

## 产品验收

以下是拟定的验收场景和预期结果。每条 P0 验收应有可复现输入、操作步骤和结果记录。

| 编号 | 场景与操作 | 通过标准 |
| --- | --- | --- |
| P0-01 | 线上、现场或混合、导入各走一次流程 | 各自显示可证实的音源。结束或导入完成后进入对应会议的同一整理工作区。刷新后仍能定位本次记录 |
| P0-02 | 录音已落盘，实时识别中断后结束会议 | 已保存音频和文字可查看。界面区分已存待识别与实际音频缺失。重试后不会重复生成同一范围的有效文字 |
| P0-03 | 中英混说，会中打开双语视图 | 中文保留原文，英文在确认后显示中文译文。原文和译文定位到同一音频范围，缺译或失败有可见状态 |
| P0-04 | 译文生成中修改原文，或译文任务失败 | 迟到译文无法覆盖当前有效版本。受影响条目显示过期或待翻译。原文可读、可回听，允许补译 |
| P0-05 | 用四类合成样本分别生成草稿 | 每类出现对应的重点字段。未明确的负责人、日期或承诺显示待确认。面试草稿区分候选人陈述与人工评语 |
| P0-06 | 核对一条决定或待办，回听后保存人工编辑，再生成新草稿 | 能定位实际原文和音频。新草稿可对比，人工修改与既有采用版本可找回 |
| P0-07 | 同一采用稿包含内部风险、个人备注、未确认承诺和明确可分享条目，分别制作内部版与对外版 | 对外版只包含明确选入的内容。预览与 Word、PDF、Markdown 导出的内容一致。内部版与对外版可分别找到和重复导出 |
| P0-08 | 对外预览后修改来源或采用稿，再确认交付 | 页面要求重新核对预览。此前确认的交付快照仍可查看，文件导出状态与已发送状态可区分 |
| P0-09 | 确认一个有负责人与截止日期的行动项，重新打开会议并开始系列下一场 | 待办状态持久保存、可回到来源。同一行动项重复确认不会产生两条有效跟进记录。下一场可见未完成事项 |
| P0-10 | 用中文搜索只在英文会议中出现过的约定 | 有效中文译文可被检索，结果标明译文并可跳到原话和录音。个人备注按默认范围排除 |
| P0-11 | 加载旧会议、旧采用稿、旧交付件，或让翻译和生成服务不可用 | 可回看及导出既有成果。可保存录音或手工整理。缺少语言与译文数据的旧记录显示兼容状态 |
| P0-12 | 实际线上和混合场景回听可辨识声音，分别核对音源、异常状态及结束保存 | 记录本机配置与可核验的回听结果。真实设备项目单列验收，合成回归不替代设备证据 |

## 规格审核与验证准备

现有结构为 React／TypeScript 前端、FastAPI 服务、SQLite 数据、Swift 原生宿主及采集。后端行为可在 `app/` 与 `tests/` 对照，前端工作流在 `frontend/src/features/`，交付和硬件验证说明位于 `docs/engineering/`。沿用现有 Python 类型校验、TypeScript 明确类型和 Prettier 约定。实际样例可参考 `app/languages.py` 中的 `configure_asr(provider, language)`，语言规范化集中处理。

以后实施时用隔离数据和合成样本核对 P0-01 至 P0-11，按适用场景补实际模型冒烟和界面验收。P0-12 另记实机证据。现有基线命令如下，本文所列产品验收是目标条件。

```bash
.venv/bin/python -m pytest tests/test_language_policy.py tests/test_meeting_handoff.py tests/test_delivery_readiness.py tests/test_handoff_followup.py tests/test_retrieval_languages.py -q
npm --prefix frontend run typecheck
npm --prefix frontend run test:stream
npm --prefix frontend run format:check
npm --prefix frontend run build -- --outDir /private/tmp/tingji-workflow-build --emptyOutDir
bash scripts/test_host.sh
```

始终保留原音、原文、人工修改和已确认交付件，并按来源版本核对派生内容。数据库迁移、新依赖、云端发送范围和发行安排留到相应阶段明确。私有会议原文、音频与凭据不纳入版本库。产品设计和实施均沿用本机数据、云端确认及采集权限边界。

中英覆盖、对外版按条目选入和翻译缺口的处理已纳入本轮模块规格。规格与任务进入评审。
