# 录音可靠性验收

更新：2026-10-19。目标为 M4 Max 本机服务，覆盖浏览器麦克风、电脑声音和混合音源。

## 已完成的机制验证

| 场景 | 结果 |
|---|---|
| 缺段、空分段、服务重启 | 自动测试通过；缺段被指出且阻止完成，补齐后原始字节顺序一致 |
| 尾段及重复完成 | 自动测试通过；最终数据先于保存，合并不重复，重复完成不重复创建会议或简记 |
| 录音器已经自行停止 | 自动测试通过；不会等待第二次停止事件而卡在保存中 |
| 原生采集仍在运行 | 自动测试通过；健康检查不续期采集心跳，恢复界面禁用完成按钮 |
| 浏览器暂存不可用 | 自动测试通过；仍可发现服务器已有录音 |
| 浏览器残留已完成会话 | 自动测试通过；不重复显示为待恢复 |
| 预览、失败、重叠成功结果 | 自动测试通过；只有成功范围计入覆盖，重叠不重复计时 |
| 脱敏诊断 | 自动测试通过；内容、密钥、模型身份、路径、会话 ID、原始错误均不导出 |
| 隔离页面端到端 | 通过：缺段恢复卡片、简记回看、诊断下载；12 秒合成音轨启动、简记、暂停、结束、暂不处理并打开会议 |

运行：`PYTHONPATH=. .venv/bin/pytest -q`、`npm --prefix frontend run test:stream`、`npm --prefix frontend run build`。

重复页面验收：在项目根目录运行 `PYTHONPATH=. .venv/bin/python scripts/recording_ui_fixture.py`，访问 `http://127.0.0.1:8766/`。它创建临时数据库和一条缺中间分段的测试录音；在录音设置选择“电脑声音”后，开始录音只使用固定 12 秒合成音轨，不调用 macOS 采集器或麦克风。可验证简记、暂停、结束和暂不处理；实时识别窗口固定返回未就绪，不加载 ASR。退出时清理临时业务数据；浏览器下载的诊断文件和本域浏览器暂存由浏览器保留。不要将真实资料导入此测试服务。

页面测试使用临时数据库和合成音轨，没有开启真实麦克风。12 秒合成测试不能代替长会议实录。字节数和元数据时长也不能证明音频可听、有效发言完整或识别准确。

## 待完成的实录矩阵

以下均为待验收，未作为通过结果。使用经允许的测试会议或可公开播放的音频，记录版本、浏览器、音源和识别模式。

| 场景 | 时长／操作 | 验收方法 |
|---|---|---|
| 三种音源基线 | 每种 30 分钟 | 原音首、中、尾可听；简记可回听；无缺段；对照外部计时核对暂停时间线 |
| 长会议与资源趋势 | 电脑声音 60／120 分钟 | 分段持续落盘；记录内存、磁盘与识别滞后；快速完成补齐尾段且无重复 |
| 切后台 | 其他应用至少 10 分钟 | 保持亮屏状态可信、采集不断，切回立即刷新状态 |
| 暂停／恢复 | 长短间隔各 3 次 | 暂停期间保持亮屏；恢复后音频顺序和简记位置正确 |
| 短暂服务不可达 | 测试环境阻断本机 API 30 秒后恢复 | 浏览器继续暂存，联网后可重试同步；不将未同步显示为本机落盘 |
| 长时间失联 | 原生页面失联超过 5 分钟 | 按既有规则停止采集，原音可恢复，不承诺此后仍在录音 |
| 刷新／关闭 | 主动接受离开提示后重新打开 | 恢复中心展示已有内容；缺段未补齐不能完成；不自动重启采集 |
| 服务重启 | 隔离环境重启服务 | 已存音频与简记保留；未完成识别标为失败；恢复前后音频一致 |
| 音源消失／设备断开 | 停止播放或断开麦克风 | 音源与保存状态分开提示；原音保留；不将静音当成识别成功 |
| 空间不足 | 仅用测试卷或隔离浏览器配额模拟 | 明确警告并暂停浏览器录音；有内存中未保存内容时不能直接关闭工作台 |

每次记录：日期、提交号、音源、引擎、标准／短片段模式、实际时长、暂停次数、首尾回听、分段缺口、快速完成尾段核对、最大内存和诊断文件。未通过项附最小复现步骤；真实音频需先确认可用于调试。

恢复只整理已存内容，不录制中断期间的声音，不把缺段拼成“完整录音”，不自动续录。没有保存下来的尾段无法凭空补回。

## 2026-11-03：空失败会话与恢复录音分开

未获屏幕与系统音频录制权限的原生启动会留下零时长会话。以前仅凭 `source=macos` 就进入恢复中心，导致“有 1 条录音、0 MB、缺段 0”的误导。现在空失败会话不计入恢复录音条数，单独展示失败原因；原生音轨不再显示浏览器分段的“缺段 0”指标。读操作不续期采集心跳。

仅在采集已停止、未发布，且没有音频、临时音频、简记、会议准备或识别尝试时，允许可逆收起。会话和文件均保留，历史中可以恢复显示；任何已有内容都会拦截收起。服务端使用采集锁后再取得记录锁，与采集启动的锁顺序一致。

验证：恢复清单计数、浏览器尚未同步内容、权限失败原因脱敏、活动采集、已存材料保护、可逆收起和恢复显示。隔离界面命令为 `scripts/recording_ui_fixture.py --empty-recovery-demo --port 8766`，无真实采集或模型调用。
