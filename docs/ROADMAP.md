# 听记迭代路线

更新时间：2026-10-13。以下为本项目开发路线，未设置后台自动任务或承诺上线日期。

## A. 实时结果复用与快速完成（已实现）

- SQLite 保存实时识别尝试，绑定录音 ID、音源、引擎、16 kHz 帧范围、音频 SHA-256、模型身份、完成/失败状态、原始结果和错误。
- 成功结果可按相同范围、音频及模型身份幂等复用；失败记录保留，重启时未完成请求标记失败。
- 显示覆盖时长、未覆盖范围、失败次数和近期失败详情；刷新/中断后缓存保留。
- 停止前选择快速完成或精细处理。快速完成固定成功结果快照，复用已有文字，从完整原音补识别缺段和尾段；静音已处理范围也计入覆盖。
- 快速稿保留粗时间戳、未分配发言人；用户可再运行现有精细转写，保留版本历史。并发人工修改触发候选稿，不覆盖用户编辑。
- 旧录音没有新增的实时缓存时，快速完成会补识别全部音频。覆盖完整性表示所有音频范围已处理，不代表文字准确率。

## B. Qwen 逐字/增量文字推送（下一阶段）

先保留现有分段采集方式，接入本机 MLX `stream_transcribe`，通过 SSE 或 fetch 流发送开始、文字增量、最终结果、失败事件。每个事件绑定录音 ID、引擎、音频范围和递增序号；客户端处理重复、断流和 UTF-8 边界。部分文字作为临时显示，只有最终结果写入 A 的可复用缓存；异常时不把部分文字当作完整覆盖。自动跟随支持文字增长，暂停回看仍保留视图。原有整批接口保留为回退路径；Whisper 首先继续分段更新。

验收：使用真实模型证明第一批文字在完整识别结束前到达；最终文字与累计增量一致；断流后的部分结果不进入成功缓存；停止与暂停不等待推送结束。不用打字动画模拟模型流式输出。

## C. 短片段与临时文字修订（紧随 B）

- 引入模型常驻进程与任务生命周期管理，避免每片段重新加载模型；与正式转写协调 GPU 和统一内存占用，保留停止与释放模型入口。
- 先试验约 3–5 秒音频片段和短上下文重叠，结合静音检测确定断句；普通话短句、多说话人、噪声、连续长句分别测量。
- 结果区分“临时文字”与“已确认文字”。滚动窗口修订只替换未确认尾部，按范围和版本去重；确认后才能进入复用缓存或转为可信原文引用。
- token 输出的估算时间不作为字词精确时间戳；正式稿继续使用精细对齐。

验收：记录首字延迟、确认延迟、文字修订次数、重复/漏字、实时率和内存峰值；对照现有 15 秒模式评估质量，不仅比较速度。测试暂停、耳机、页面刷新、采集器退出和长会议。

## D. 简记扩写与依据关联

对简记附近的已确认文字或正式稿范围做检索，LLM 输出扩写建议和有效片段引用，保留用户原文；缺少证据不补造人名、日期、责任人。用户接受后写入独立字段。随后推进跨会议 SQLite-vec 检索与引用回听。
