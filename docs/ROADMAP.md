# 听记迭代路线

更新时间：2026-10-14。以下为本项目开发路线，未设置后台自动任务或承诺上线日期。

## A. 实时结果复用与快速完成（已实现）

- SQLite 保存实时识别尝试，绑定录音 ID、音源、引擎、16 kHz 帧范围、音频 SHA-256、模型身份、完成/失败状态、原始结果和错误。
- 成功结果可按相同范围、音频及模型身份幂等复用；失败记录保留，重启时未完成请求标记失败。
- 显示覆盖时长、未覆盖范围、失败次数和近期失败详情；刷新/中断后缓存保留。
- 停止前选择快速完成或精细处理。快速完成固定成功结果快照，复用已有文字，从完整原音补识别缺段和尾段；静音已处理范围也计入覆盖。
- 快速稿保留粗时间戳、未分配发言人；用户可再运行现有精细转写，保留版本历史。并发人工修改触发候选稿，不覆盖用户编辑。
- 旧录音没有新增的实时缓存时，快速完成会补识别全部音频。覆盖完整性表示所有音频范围已处理，不代表文字准确率。

## B. Qwen 逐字/增量文字推送（已实现）

保留约 15 秒分段采集方式，接入本机 MLX `stream_generate` 的真实 token 生成，通过 fetch/NDJSON 流发送开始、累计文字、最终结果、失败事件。累计解码会等待完整中文字符，避免逐 token 解码破坏 Unicode。每个事件绑定录音 ID、引擎、音频范围、请求 ID 和递增序号；客户端处理重复、断流和 UTF-8 边界。部分文字标为“生成中/未确认”，只作临时显示，只有最终结果写入 A 的成功缓存；异常时不把部分文字当作完整覆盖。

自动跟随支持文字增长；回看不会被增量更新拉回底部。停止或关闭窗口会取消流式识别，终止子进程并释放实时锁；快速完成补识别尚未确认的范围。暂停时可让已提交窗口继续完成。Qwen 默认开启“逐字推送”，录音前可关闭以回到整批接口；Whisper 继续分段更新。

验证：真实本机 Qwen 和中文合成音频产生了多个部分事件，首批文字确实先于最终结果到达，最后一条累计文字与最终结果一致；部分阶段覆盖为 0，最终提交后才计入覆盖。自动测试包括取消后子进程退出/锁释放、部分失败不提交、重试、缓存重放、Unicode 跨字节、重复/丢失事件、请求标识混杂和缺少最终事件。本阶段没有缩短采集窗口，也没有模型常驻。

## C. 常驻模型、短片段与临时修订（试用已实现，实录评估待完成）

- Qwen 使用单一常驻子进程，按请求 ID 串行处理，模型身份变化时重载。可在录音前预加载，查看状态并释放；空闲约 3 分钟自动卸载。断流/取消会终止进程，下一次重新加载。
- 正式任务与实时识别共用资源锁；正式任务等待正在识别的窗口结束，再释放常驻模型后处理音频或分析，避免并行争用统一内存。等待可取消。
- 保留标准约 15 秒模式，新增“短片段与尾部修订（试用）”，默认关闭。约 5 秒、10 秒分别识别同一个未确认窗口，累计上下文修订临时尾部；最长 15 秒、暂停或约 0.8 秒低能量静音后确认。静音检测为能量启发式，不是精确语音端点模型；不同麦克风、噪声环境可能提前分段，尚需实录对比。
- 已确认边界保持不可变，后续上下文仅更新当前临时尾部。预览尝试状态为 `preview`，不保存可复用文字、不计覆盖、不可转为简记；只有确认结果进入实时缓存和快速稿。
- 显示本次请求首字时间、处理时长、RTF（处理时长/输入片段时长）、窗口确认滞后及临时尾部更新次数。首字时间从提交识别请求起计，不包含采集窗口等待；确认滞后相对于音频窗口结尾，不是精确语音端点延迟。峰值内存为进程观测值。
- 修复原生整批请求未传递所选引擎的问题；关闭逐字推送时仍尊重 Qwen/Whisper 选择。

已验证：常驻模型复用、身份变化重载、取消杀进程并重建、空闲释放、正式任务接管、预览不进入覆盖、累计窗口确认、暂停/静音确认、PCM 前缀与剩余音频一致性。真实本机 Qwen 的中文合成样例只加载一次，分别处理 5/10/15 秒输入并展示了临时尾部的补全；仅 15 秒确认结果可复用。

待验收：普通话短句、连续长句、多说话人、噪声、耳机与长会议实录；与标准模式比较重复/漏字、修订次数和真实首字/确认延迟。首版试用暂不自动替换用户默认标准模式，也不声称优于完整转写。

## D. 简记扩写与依据关联（首版已实现）

- 在录音结束后的当前文字稿中选取简记附近范围（前 120 秒、后 60 秒），优先保留最近的完整片段，并遵守模型上下文预算。
- 使用现有本地／云端 LLM 配置，队列生成独立扩写候选；支持进度、取消和失败提示。无附近文字稿时直接返回依据不足。
- 同时校验片段 ID 和原文连续摘录，提供引用回听；用户核对并接受后保存到独立字段，不修改原始简记或文字稿。
- 候选绑定文字稿版本、简记原文、类型和位置；输入改变后标记过期并拦截接受。已接受结果在文字稿更新后提示待复核。
- 首版尚不在录音过程中生成扩写，引用存在无法机械保证语义充分，保留人工确认。

## E. 跨会议本地检索（首版已实现）

- 统一当前文字稿、原始简记、当前已接受扩写及用户保存的纪要的检索单元，绑定来源版本、片段与音频范围；候选及过期派生内容不参与搜索。
- 关键词搜索直接可用；语义／混合检索通过单独选择本机 Embedding 模型建立 SQLite-vec 索引，不使用云端向量服务。
- 索引队列支持批量进度、取消和缺段续建；缓存绑定模型身份、维度、服务地址、前缀及单元版本，输入变化后失效。原音及会议资料保留。
- 按会议和资料类型筛选，显示原文内容、来源和版本，打开时重新校验指纹并支持音频回听。
- 首版仅返回检索资料，不生成跨会议回答。采用精确余弦扫描，适合中小规模本机资料库；较大规模后续评估 vec0 与索引后台化。

## F. 质量评估与引用约束问答（待推进）

用真实普通话会议评估向量模型召回与排名，建立包含人名、项目、决策和待办的检索评测集；再接入检索后的问答，每项回答绑定可核验来源，证据不足时不形成确定结论。同时继续短片段实录对比，检验重复／漏字、修订和延迟，实测前保持试用开关。
