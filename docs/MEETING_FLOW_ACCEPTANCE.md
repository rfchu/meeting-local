# 会议全流程验收

## 范围与数据

本次把已有录音、简记、原文核对、纪要和待办串起来，并补上会前准备、持久关注点处理状态、纪要输入绑定和跨会议跟进。会议详情主入口为准备、整理、成果，原文及分析仍可独立使用。

数据库版本 13：新增 meeting_preparation（本机单份准备草稿）、meeting_briefs（随会议保存的准备）、attention_reviews（核对后的表述、用途、原文及指纹）；note_todos 扩展会议纪要来源和关注点确认来源。旧记录不自动认定为已核实事实；原音、文字稿、原始简记和历史纪要保留。

注意边界：

- 会议准备只有计划信息，不能证明实际讨论、到场或形成决定。计划参会人不直接填入实际参会者列表。
- 个人和暂不处理的原始简记不加入 AI 纪要上下文。原始个人记录可核对出一条单独的可用表述，原始正文仍保持个人属性；只有已确认表述及其依据进入模型。
- “确认纳入会议成果”表示可参与整理，尚未表示已经写入纪要。“相关原文被引用”只比较来源片段关联，不保证语义覆盖。明确采用的计数以人工复制采用及版本来源为依据。
- 只有 AI 纪要使用准备和已确认关注点；规则纪要保留既有分析流程。个人备注的 AI 扩写是另一项明确操作，沿用原有本地／云端模型提示。
- 跟进在本机管理；不自动通知、共享或同步外部系统。不自动推断负责人、日期，也不自动把新纪要中的行动项批量变成任务。
- 完成录音时仅在准备草稿仍与本次内容相同时清理该草稿，不覆盖另行保存的新草稿。草稿不是多用户协作文档；多个窗口保存时仍按最后写入生效。

## 自动回归

运行 `PYTHONPATH=. .venv/bin/pytest -q`、`npm --prefix frontend run test:stream`、`run build`、`run format:check`。

新增 tests/test_meeting_flow.py 验证：

1. 准备草稿恢复、浏览器／原生录音绑定、旧客户端元数据重试不清空准备。
2. 完成旧会话不清除较新的准备草稿、关联会议存在性及禁止自关联。
3. 纳入成果要求人工确认、当前记录指纹／文稿版本、非空内容和附近原文，拒绝虚构或远处引用。
4. 个人／暂不处理记录不进入纪要上下文，确认表述与私人原始记录保持分离。
5. 生成期间准备或关注点变化阻止发布；人工保存保留来源上下文；旧版本保存、来源过期的润色被拦截。
6. 已核对个人记录可明确采用到纪要；改为个人保留后旧采用、检索和相关核对失效。
7. 纪要行动项人工确认、去重、跟进完成、跨会议读取及来源过期提示。
8. 关注点转出跟进后撤回会议用途只标记待复核，不删除既有跟进；删除记录／会议清理新关联数据。
